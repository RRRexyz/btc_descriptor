# 08 输入数据最小规范（点云 + 位姿）

本文只规定两件事：**`pcds_dir` 里的 PCD 帧**和 **`pose_file` 的 8 列位姿**。这是把自有数据喂给 `btc_place_recognition` 的最小契约。

`.bin` 分支、`setting_path` 的 YAML、ROS 参数、数据质量要求、生成脚本与自检工具见 [06-输入数据格式.md](06-输入数据格式.md)。

| 输入 | 参数名 | 形态 | 读它的代码 | 格式错了会怎样 |
| --- | --- | --- | --- | --- |
| 点云序列 | `pcds_dir` | 一个目录，内含 `000000.pcd` … `%06d.pcd` | `read_lidar_data`（`src/example/place_recognition.cpp:13`） | 坏帧/缺帧 → 报 `[ERROR] Couldn't read file` 并**跳过该帧继续**（不中断整条序列） |
| 位姿 | `pose_file` | 文本，每行 8 列 `id x y z qx qy qz qw` | `load_evo_pose_with_time`（`src/src/utils.cpp:138`） | 行被**静默丢弃**或列错位 → 位姿全错，不报错 |

两者必须来自**同一套坐标系约定**：点云是传感器系下的单帧原始扫描，位姿把这一帧搬到世界系（`p_world = R · p_sensor + t`）。

---

## 1. `pcds_dir`

### 1.1 目录与命名

```
my_dataset/
├── velodyne/          ← pcds_dir 直接指向这一层
│   ├── 000000.pcd
│   ├── 000001.pcd
│   └── ...
└── pose.txt           ← pose_file
```

- 文件名固定 **6 位零填充**（`%06d`），从 `000000` 起**连续**递增；第 `k` 个文件对应 `pose_file` 第 `k` 行（0 基）。
- `pcds_dir` 必须指向**直接装有帧文件的目录**；指到数据集根目录会找不到 `000000.pcd`。
- 用**绝对路径**：`roslaunch` 启动时进程工作目录是 `~/.ros`，相对路径会解析到那里。
- 必须设 `read_bin=false`（默认 `true` 时按 `%06d.bin` 找文件，PCD 会全部打不开）。

### 1.2 文件内容

最小可用头部（`DATA binary`）：

```text
# .PCD v0.7 - Point Cloud Data file format
VERSION 0.7
FIELDS x y z intensity
SIZE 4 4 4 4
TYPE F F F F
COUNT 1 1 1 1
WIDTH 14903
HEIGHT 1
VIEWPOINT 0 0 0 1 0 0 0
POINTS 14903
DATA binary
<紧跟 POINTS × 16 字节的点数据>
```

- `FIELDS` 必须包含 `x y z`，**顺序任意**（PCL 按名字取列）；`intensity` 可省略，省略时 `SIZE`/`TYPE`/`COUNT` 也只写 3 项。
- `TYPE` 必须是 `F`（float32）；整数类型的 `x y z` 对本算法没有意义。
- `WIDTH × HEIGHT` 必须等于 `POINTS`；`binary` 模式下实际字节数要够 `POINTS × 每点字节数`。
- `DATA` 只支持 **`ascii`** 与 **`binary`**；`binary_compressed`（LZF）读不了，日志表现为 `[ERROR] ... Couldn't read file .../000005.pcd`。

### 1.3 语义与容错

- 点云写在**位姿对应的传感器系**下，不要预先乘位姿（否则会被二次变换）。单位米，z 向上。
- PCD 分支读到坏文件/缺文件时是 **`continue`**：报一行 `[ERROR] Couldn't read file ...`，**跳过这一帧继续**后面的帧。所以“能跑完”不等于“数据齐”，要自己核对帧数。
- 不要有 0 点帧：后续平面提取会拿到空云，白跑一帧。

## 2. `pose_file`

### 2.1 行格式

每行**恰好 8 个 token，用单个空格分隔**，一帧一行，行序 = 帧序：

| 列 | 内容 | 说明 |
| --- | --- | --- |
| 1 | `id` / `time` | 任意数值，读入后**从未使用**，可放序号或时间戳 |
| 2–4 | `x y z` | 米，传感器原点在世界系中的位置 |
| 5–8 | `qx qy qz qw` | 旋转四元数，**实部 `w` 在最后一列** |

样例：

```text
0 4.000000 4.000000 1.600000 0.000000 0.000000 0.000000 1.000000
1 4.400000 4.000000 1.600000 0.000000 0.000000 0.000000 1.000000
```

### 2.2 语义

- 位姿是 **lidar → world**：`p_world = R · p_lidar + t`，`t` 是雷达光心在世界系的位置。
- 位姿的传感器系必须与点云的坐标系是**同一个安装点**（KITTI 的 cam0 位姿配 velodyne 点云是经典错配，需要先乘外参）。
- 四元数**必须是单位四元数**：代码不做归一化，`||q|| ≠ 1` 会得到带缩放的旋转矩阵，点云被拉变形且不报错。
- 行数应等于帧数；多了不会被读，少了会少处理帧。

### 2.3 解析陷阱

解析是 `getline(sin, info, ' ')`，严格按**单空格**切分：

| 写法 | 后果 |
| --- | --- |
| `0 1 2 3 0 0 0 1` | ✅ 正常 |
| 连续两个空格 | ❌ 切出空 token → 该行解析为 0 → **后面所有列整体错位**，不报错 |
| 用 Tab 分隔 | ❌ token 数 < 8 → 该行被丢弃 |
| 只有 7 列 | ❌ 该行被丢弃 |
| 多于 8 列 | ⚠️ 只取前 8 列 |
| 行尾多一个空格 / 有空行 | ✅ 尾随空格无害；空行被忽略 |

注意日志里的 `Total submap number:N` 打的是 **pose 行数**，不是实际处理的帧数，不能用它判断数据是否读全。

## 3. 最小自检

```bash
PCDS=/abs/path/my_dataset/velodyne
POSE=/abs/path/my_dataset/pose.txt

ls "$PCDS" | wc -l             # 帧文件数，应与下一行相等
wc -l "$POSE"                  # 位姿行数
ls "$PCDS" | head -3           # 必须是 000000.pcd 起步的 6 位序号
head -11 "$PCDS/000000.pcd"    # DATA 是 ascii/binary；FIELDS 含 x y z
awk '{print NF}' "$POSE" | sort -u   # 唯一输出应为 8
python3 -c "import numpy as np; a=np.loadtxt('$POSE'); \
print('max |‖q‖-1| =', np.abs(np.linalg.norm(a[:,4:8],axis=1)-1).max())"
```
