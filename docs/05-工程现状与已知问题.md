## 2. 🔴 潜在越界与数据竞争

### 2.1 `match_array` 固定 20000，帧号越大越界

`src/src/btc.cpp:1657` 附近：

```cpp
double match_array[20000] = {0};       // 栈上固定大小
// ...
match_array[data_base_[...][...].frame_number_] += 1;   // frame_number_ 作下标
```

`BTC::frame_number_` 直接来自 `frame_id`（即帧序号）。**序列长于 20000 帧就会写越界**。KITTI 00（4541 帧）安全，长序列（多 session 拼接、城市级数据集）必须先改这里。

### 2.2 `frame_number_` 是 `unsigned short`

`src/include/btc.h:80`：`unsigned short frame_number_;`，而 `GenerateBtcDescs` 的入参是 `int frame_id`。超过 65535 帧会静默回绕，导致时间间隔判断（`skip_near_num_` 过滤）彻底失效。

### 2.3 `useful_match` 是 `vector<bool>`，却在并行循环里被写

`src/src/btc.cpp:1588` 声明 `std::vector<bool> useful_match(...)`，在 `src/src/btc.cpp:1640` 的 `par_unseq` lambda 里写 `useful_match[i] = true;`。

`std::vector<bool>` 是位压缩特化，**相邻 8 个下标共享同一个字节**。多线程同时写不同下标（同一字节）是数据竞争，可能丢失更新（表现为少量描述子被判定为"未命中"）。正确写法：改用 `std::vector<char>` / `vector<uint8_t>`，或每线程独立缓冲再合并。

### 2.4 并行 lambda 中用 `data_base_[position]` 非 const 访问

`src/src/btc.cpp:1628-1640`：虽然外层有 `find` 保护、命中后不会插入，但 `operator[]` 是非 const 操作。实践上不会崩溃（无插入即无 rehash），但属于并发安全隐患，建议先 `auto &vec = iter->second;` 再按下标访问。

### 2.5 直方图分箱下标可能越界

`src/src/btc.cpp:1240`：

```cpp
int cut_num = (dis_threshold_max - dis_threshold_min) / high_inc;   // (4 - (-1))/0.1 = 50
std::vector<double> cnt_list;                                       // size = 50
int cnt_index = (dis - dis_threshold_min) / high_inc;               // dis ∈ [-1, 4]
cnt_list[cnt_index]++;                                              // dis == 4.0 时 index == 50 → OOB
```

点恰好落在 `proj_dis_max` 上时会越界写。概率低但确实是缺陷，改成 `std::min(cnt_index, cut_num - 1)` 即可。

### 2.6 `summary_` 是 `unsigned char`

`src/include/btc.h:73`。当前 50 bit（`(4−(−1))/0.1`）远小于 255，安全；但若调大 `proj_dis_max` 或调小 `proj_image_high_inc` 使箱数超过 255，`summary_` 会溢出，NMS 与截断的顺序全部错乱。

## 3. 🟡 逻辑瑕疵（不崩溃，但行为与命名/注释不符）

### 3.1 `OctoTree` 不是八叉树

`src/include/btc.h:167` 定义了 `leaves_[8]`、`octo_state_`，但 `grep` 全文件**没有任何读写**。`init_octo_tree()`（`src/src/btc.cpp:128`）只做一件事：点数够就拟合平面，**没有递归细分**。

实际语义：`OctoTree` = 一个固定边长体素 + 一次 PCA 平面拟合。多分辨率能力不存在。

### 3.2 投影平面的"法向去重"实际失效

`src/src/btc.cpp:1046`：

```cpp
if ((proj_normal - last_normal).norm() < 0.3 || (proj_normal + last_normal).norm() > 0.3)
```

两个单位向量相加的范数几乎总大于 0.3（同向时约为 2），第二个条件近乎恒真 → 整个判断近乎恒真。

后果：`proj_plane_num_` 的实际效果退化为"**取点数最多的前 N 个合并平面**"，而不是"取 N 个法向不同的平面"。在只有一个大平面的场景里（如长直走廊、开阔广场）影响不大；在双向立面场景里可能把同一面墙用两次。

### 3.3 `angle_` 读取未初始化变量

`src/src/btc.cpp:1508` 附近声明 `Eigen::Vector3d normal_1, normal_2, normal_3;` 后**从未赋值**，却用于

```cpp
single_descriptor.angle_[0] = fabs(5 * normal_1.dot(normal_2));
```

`angle_` 是随机值。所幸全仓库无人读取该字段，属半成品；若将来要用，必须自己赋值。

### 3.4 `binary_similarity` 的注释写错

`src/src/btc.cpp:107` 注释称"hamming distance"，实际实现是

```cpp
dis = 两向量同为 true 的位数;  return 2 * dis / (b1.summary_ + b2.summary_);
```

即 **Dice / F1 系数**（0~1，越大越相似），对"两向量都稀疏"天然宽容。理解召回/精度特性时按 Dice 分析，不要按汉明距离分析。

### 3.5 两轮平面合并语义重叠、且都是 O(n²)

`get_project_plane`（`src/src/btc.cpp:814`）先合并一轮并**丢弃未合并的单片**；`merge_plane`（`:924`）在结果上再合并一轮并**保留单片**。两函数代码几乎相同（判据、协方差合并公式一致），相当于把 `O(n²)` 算了两遍。

第一轮丢掉单片再被第二轮"允许单片"的逻辑并不构成完整的兜底（被丢的单片已经不存在了），更像两次重构的叠加。若做性能优化，这是第一个可砍的地方（可合并为一轮 + 保留单片）。

### 3.6 `plane_cloud_vec_.back()` 的隐式时序耦合

`candidate_verify`（`src/src/btc.cpp:1807`）用 `plane_cloud_vec_.back()` 当作"当前帧平面"。

这要求调用方**必须先对当前帧调 `GenerateBtcDescs`、再调 `SearchLoop`**。示例代码确实满足（`place_recognition.cpp:184` → `:195`），但这是一个藏在实现里的契约：任何把 `SearchLoop` 抽出来单独测试、或并行处理多帧的改造都会静默取错帧。建议改成显式传入当前帧平面，或用 `frame_id` 查表。

### 3.7 YAML 缺键会静默变 0

`cv::FileStorage` 对不存在的键返回空节点，赋值给数值类型得到 0。`voxel_size_ = 0` 会让体素化完全失效（所有点挤进同一体素）。没有任何 key 校验或日志。**改配置后务必看打印的 `Sucessfully load config file` 是否出现，并检查关键值**（顺带一提，这行提示把 "Successfully" 拼成了 "Sucessfully"）。

## 6. 二次开发建议（按优先级）

1. **修数据竞争**（§2.3 `vector<bool>`，1 行改动：改 `vector<char>`）——成本最低、收益明确。
2. **修越界**（§2.1 `match_array[20000]`、§2.5 分箱下标）——换长序列前的必要前置。
3. **接上 `PlaneGeomrtricIcp`**（§4.1）——让回环输出可用的 6DoF 位姿，才能喂给位姿图。
4. **合并两轮平面合并**（§3.5）——直接砍掉近一半的 `GenerateBtcDescs` 耗时。
5. **把 `plane_cloud_vec_.back()` 改成显式参数**（§3.6）——解锁多帧并行与单元测试。
6. **参数外提**（§5 魔法数字）——把 `candidate_verify` 的阈值放进 YAML，便于按数据集调优。
7. **删除死代码**（§4.2–4.5）——`CustomMsg.h`/`CustomPoint.h`、`point_list_3d`、`connect_*`、重复的 `pubPath`。

## 7. 快速自检清单

把项目移植到新环境 / 新数据集时，按此清单逐项确认：

- [ ] `catkin build btc_desc` 通过（Ceres 版本分支是否正确命中？）
- [ ] YAML 首行是 `%YAML:1.0`，且 25 个键名逐字正确（特别注意 `max_constrait_dis`、`triangle_resolution`）
- [ ] 点云文件从 `000000.bin` 连续编号
- [ ] 位姿文件是空格分隔的 `id x y z qx qy qz qw`（8 列）
- [ ] 序列长度 < 20000（否则改 `match_array` 大小）且 < 65536（否则改 `frame_number_` 类型）
- [ ] 二值描述子箱数 < 255（`summary_` 上限）
- [ ] 明确这是**离线批处理评估器**（跑完全部帧即退出，无 `ros::spin`）；打印的耗时只覆盖 `GenerateBtcDescs` / `SearchLoop` / `AddBtcDescs`，不含可视化发布与 `ros::Rate` 互斥节流（`loop` 为 50 kHz、`slow_loop` 为 1 kHz，开销很小但整体运行时间会明显长于三者之和）
