# 02 数据链路

本文按"数据从磁盘进 → 描述子出 → 回环结果出"的顺序拆解整条链路。每一节给出：**输入 / 输出 / 关键参数 / 代码位置**，并在末尾汇总中间容器的增长情况与耗时分布。

## 2. 位姿加载 `load_evo_pose_with_time`

`src/src/utils.cpp:138`，被 `src/example/place_recognition.cpp:100` 调用。

```cpp
// 8 列文件的解析过程（number 为该行已读入的列序号）
// number == 0            → time_list.push_back(stod(info))     // 第 1 列进入 time_list
// number == 1..7         → temp_matrix[number-1] = stod(info)  // 后 7 列填入 1×7 向量
// number == 7 时提交：
//   translation = temp_matrix[0..2]
//   q = Eigen::Quaterniond(temp_matrix[6], temp_matrix[3], temp_matrix[4], temp_matrix[5])
//       即 q(w, x, y, z) ← 第 7 列是 w
```

因此它接受的文件格式是 **`time/id  x y z  qx qy qz qw`**。仓库内 `src/poses/kitti00.txt` 正是这种布局（首列是帧号），可以无缝喂进去：首列落进 `time_list`（后续未被使用），后 7 列被正确解释为平移 + 四元数。

> 注意文件里**首列不会**被当作时间戳使用，`time_list` 只被读取用来对齐长度，实际从未参与计算。

## 3. 主循环：逐帧处理

`src/example/place_recognition.cpp:119`，`for (size_t submap_id = 0; submap_id < pose_list.size(); submap_id++)`。

一个迭代内的严格顺序（**顺序本身是算法正确性的前提**）：

| 步 | 动作 | 位置 | 为什么必须是这个顺序 |
| --- | --- | --- | --- |
| ① | 读点云并变换到世界系 | `:129-178` | 保证描述子在同一个全局坐标系下可比较 |
| ② | `GenerateBtcDescs(transform_cloud, submap_id, btcs_vec)` | `:184` | 会把当前帧平面存进 `plane_cloud_vec_` 尾部，供后续校验取 `.back()` |
| ③ | `if (submap_id > skip_near_num_) SearchLoop(...)` | `:195-201` | **先检索、后入库**：此刻数据库中还没有本帧，天然避免自匹配 |
| ④ | `AddBtcDescs(btcs_vec)` | `:212` | 把本帧描述子写入 `data_base_` |
| ⑤ | `down_sampling_voxel(transform_cloud, 0.5)` → `key_cloud_vec_` | `:224-225` | 5 dm 降采样后的世界系点云，用于计算与历史帧的重叠率 |
| ⑥ | 发布可视化 + TP/FP 判定 | `:230-330` | — |

**坐标系变换**（`:129-154`，`.bin` 分支）：

```cpp
Eigen::Vector3d pv(points[i], points[i+1], points[i+2]);
pv = rotation * pv + translation;          // 用真值位姿把点转到世界系
pcl::PointXYZI point; point.x = points[i]; ...  // 注意：这里存的是未变换的原始坐标
cloud->points.push_back(point);            // ← cloud 在 .bin 分支里实际未被使用
transform_cloud.push_back(vec2point(pv));  // ← 真正往下传的是这个
```

也就是说：**送到算法里的是"用真值位姿配准后的世界系单帧点云"**，而非累加子图。所谓 "submap" 在代码里其实就是单帧 scan，用 `submap_id` 当帧号。这是复现时最容易误解的一点。

## 4. 描述子提取：`GenerateBtcDescs`

`src/src/btc.cpp:532`，签名：

```cpp
void BtcDescManager::GenerateBtcDescs(
    const pcl::PointCloud<pcl::PointXYZI>::Ptr &input_cloud,   // 世界系当前帧
    const int frame_id,                                        // = submap_id
    std::vector<BTC> &btcs_vec);                               // 输出：本帧全部三角形描述子
```

内部依次执行 A–F 六个阶段。

### [A] 体素化 `init_voxel_map`（`src/src/btc.cpp:758`）

- 输入：`input_cloud`（约 10 万点 / 帧，HDL-64E）
- 体素边长：`voxel_size_`（室外 2 m / 室内 0.5 m）
- 负数坐标的向下取整技巧：`if (x < 0) x = x - 1;` 再转 `int`
- 每个体素建一个 `OctoTree`，点以 `M_POINT`（`float xyz[3] + float intensity + int count`）形式塞进 `voxel_points_`
- 输出：`std::unordered_map<VOXEL_LOC, OctoTree*> voxel_map`

> **`OctoTree` 实际上不是八叉树**：`leaves_[8]` 与 `octo_state_` 在全文件中从未被读写（`grep` 无命中），`init_octo_tree()` 只做 `if (voxel_points_.size() > voxel_init_num_) init_plane();`。所以每个体素就是一层平面拟合容器，没有递归细分。

### [B] 体素内平面检测 `init_plane`（`src/src/btc.cpp:134`，并行调度在 `:792`）

- 对每个体素的点做均值/协方差，`Eigen::SelfAdjointEigenSolver` 求特征值与特征向量
- 判据（`:157`）：`if (evalsReal(evalsMin) < plane_detection_thre_)` → `is_plane_ = true`
- 平面参数：`normal_` = 最小特征值对应特征向量；`radius_ = sqrt(最大特征值)`；`d_ = -(normal_ · center_)`
- 并行方式：`std::for_each(std::execution::par_unseq, ...)`（TBB 后端），这是链接 `tbb` 的原因
- 输出：每个 `OctoTree::plane_ptr_` 被填充

### [C] 平面收集 + 两阶段共面合并

1. `get_plane`（`:797`）把 `is_plane_` 为真的体素平面汇成 `pcl::PointCloud<pcl::PointXYZINormal>`，随后 `plane_cloud_vec_.push_back(plane_cloud)`（`:545` 附近）——**这份"体素级平面点云"不参与描述子生成，只用于最后的几何校验打分**。
2. `get_project_plane`（`:814`）：第一轮合并。用 `id_` 标记归属，合并判据（两个条件都要满足）：

   ```cpp
   // 法向一致：同向或反向都算一致
   normal_diff = plane_i->normal_ - plane_j->normal_;
   normal_add  = plane_i->normal_ + plane_j->normal_;
   (normal_diff.norm() < plane_merge_normal_thre_ || normal_add.norm() < plane_merge_normal_thre_)
   // 且双方中心都落在对方平面附近
   && dis1 < plane_merge_dis_thre_ && dis2 < plane_merge_dis_thre_
   ```

   合并后按 `P_PT1 / P_PT2` 的合并公式重算 `center_`、`covariance_`、`normal_`、`radius_`、`d_`、`points_size_`，并对 `id_ == 0` 的"孤立单片"直接丢弃。
3. `sort(..., plane_greater_sort)` 按 `points_size_` 降序，然后 `merge_plane`（`:924`）做第二轮合并。与第一轮的唯一差别：**这一轮保留单片**（未并入任何组的平面原样进入结果）。
4. 兜底：若 `proj_plane_list` 为空（场景里没有可用平面），构造一个 `normal = (0,0,1)`、`center = input_cloud->points[0]` 的假平面，保证后续有投影平面可用。
5. 输出：`merge_plane_list`，按点数从大到小排好序的合并平面。

> 两个合并函数都是 `O(n²)` 双循环（n = 候选平面数，室外 2 m 体素下通常数百到数千），是本模块主要的 CPU 热点之一。

### [D] 参考平面选取与二值提取 `binary_extractor` → `extract_binary`

`binary_extractor`（`:1031`）对 `merge_plane_list` 逐个处理：

- 法向翻正：`if (proj_normal.z() < 0) proj_normal = -proj_normal;`
- 去重判据（`:1046`）：`if ((proj_normal - last_normal).norm() < 0.3 || (proj_normal + last_normal).norm() > 0.3)`
  ⚠ 两个单位向量相加的范数几乎总大于 0.3，所以这个条件近乎恒真，"跳过相似法向平面"的意图实际未生效；`proj_plane_num_` 的效果退化为"**取点数最多的前 N 个合并平面**"。
- 数量达到 `proj_plane_num_` 即 `break`。

`extract_binary`（`:1076`）对单个参照平面做投影与编码：

| 子步 | 做法 |
| --- | --- |
| 平面内正交基 | 选 `C` 分量不为 0 的分量反解一个平面内向量作 `x_axis`，`y_axis = normal × x_axis` |
| 点筛除 | `dis = signed_distance_to_plane`；`if (dis < proj_dis_min_ \|\| dis > proj_dis_max_) continue;`（室外 −1 m ~ 4 m）——只保留平面附近的点 |
| 投影到平面 | `project = point - dis * normal`，再点乘 `x_axis / y_axis` 得到二维 `(project_x, project_y)` |
| 网格化 | 分辨率 `proj_image_resolution_`（室外 0.5 m），二维网格尺寸由投影包围盒决定 |
| 深度分箱 | `cut_num = (proj_dis_max_ - proj_dis_min_) / proj_image_high_inc_`（室外 `(4-(-1))/0.1 = 50`）；每格记录被占据的箱数 → `dis_array[x][y]`；`summary_` = 占据箱数 |
| 关键点判定 | 以 `segmen_base_num = 5` 个格为一段，段内取 `dis_array` 最大值，要求 `>= summary_min_thre_`（室外 10） |
| 线状点抑制 | 可选（`line_filter_enable_`），检查 4 个方向的邻域，把落在细长结构上的候选点剔除 |
| 三维位置回投 | `coord = py * x_axis + px * y_axis + project_center`（`px, py` 为格内点的均值）→ `BinaryDescriptor::location_` |

输出：`std::vector<BinaryDescriptor>`，每个元素是 `{occupy_array_ (长度 50 的 vector<bool>), summary_ (unsigned char), location_ (Vector3d)}`。

### [E] 非极大值抑制与截断 `non_maxi_suppression`（`:1373`）

- 构建关键点 KD-tree，`radius = non_max_suppression_radius_`（配置里叫 `max_constrait_dis`，室外 2 m）
- 半径内存在 `summary_` 更大的点则丢弃自己
- 之后若数量超过 `useful_corner_num_`（500），按 `summary_` 降序截断到 500
- 结果：`binary_list` 入库 `history_binary_list_.push_back(binary_list)`（`:564`）

### [F] 三角形描述子生成 `generate_btc`（`:1425`）

```cpp
double scale = 1.0 / config_setting_.std_side_resolution_;   // 0.2 → ×5
```

1. 用 `binary_list` 的 `location_` 建 KD-tree，对每个关键点取 `descriptor_near_num_` 个近邻（室外 10 / 室内 15）。
2. 双重循环枚举三角形：`for m = 1..K-2 { for n = m+1..K-1 { ... } }`，每点最多 `(K-1)(K-2)/2` 个三角形（K=10 → 36，K=15 → 91）。500 个关键点 → 单帧上限约 1.8 万个候选三角形。
3. 三条边长 `a, b, c` 过滤：`descriptor_min_len_ ≤ side ≤ descriptor_max_len_`（室外 2~50 m）。
4. **把三边升序排序** `l1 ≤ l2 ≤ l3`，同时记录每边原属顶点（`l1 << 1, 2, 0` / `l2 << 1, 0, 3` / `l3 << 0, 2, 3` 这类位编码），以便把 `binary_A_ / binary_B_ / binary_C_` 正确对应到排序后的顶点。
5. 退化过滤：`if (fabs(c - (a + b)) < 0.2) continue;`（三点近共线）。
6. 帧内去重键：`VOXEL_LOC((int64_t)(a*1000), (int64_t)(b*1000), (int64_t)(c*1000))`，配合 `feat_map` 保证同一帧内不重复。
7. 构造描述子：

   ```cpp
   single_descriptor.triangle_ << scale * a, scale * b, scale * c;   // 边长 ×5（1/0.2）
   single_descriptor.center_   = (A + B + C) / 3.0;                  // 三点质心
   single_descriptor.frame_number_ = frame_id;
   // binary_A_ / binary_B_ / binary_C_ 按第 4 步的顶点归属填入
   ```

8. 输出：`btcs_vec`（`std::vector<BTC>`）。

> ⚠ `angle_` 字段：`angle_[0..2] = fabs(5 * normal_1.dot(normal_2))` 之类（`btc.cpp:1508` 附近），但 `normal_1/2/3` 声明后**从未赋值**，`angle_` 是未初始化的随机值，且全仓库无人读取。属于半成品字段，可忽略。

### 5.1 `candidate_selector`（`:1570`）——投票产出候选帧

对当前帧每个 `BTC`：

| 过滤 | 条件 | 作用 |
| --- | --- | --- |
| 哈希邻域 | 在该描述子的 27 个相邻整数格（`voxel_round` 三轴各 −1/0/+1）中查 `data_base_` | 允许边长量化误差 |
| 邻域半径 | `(descriptor.triangle_ - voxel_center).norm() < 1.5` | 确认落在这个立方体邻域内 |
| 时间间隔 | `(descriptor.frame_number_ - db[j].frame_number_) > skip_near_num_` | 排除时间上邻近的帧；设为负数（如 −1000000）即允许跨机/跨 session 匹配 |
| 粗距离 | `dis = (tri - tri_db).norm() < tri.norm() * rough_dis_threshold_` | 边长整体比例的相对误差门限 |
| 二值相似度 | 三对顶点相似度的均值大于 `similarity_threshold_` | Dice 系数 `2 × 交集位数 / (两向量 summary_ 之和)`（`binary_similarity`，`btc.cpp:107`，注释误写成 hamming distance） |

全部通过 → `match_array[帧号] += 1`（并行 `par_unseq` + mutex）。

之后按票数取前 `candidate_num_`（50）个帧，要求 `max_vote >= 5`，每个候选生成一个 `BTCMatchList`（含该帧全部匹配对、`match_id_`、`mean_dis_`）。

> ⚠ `match_array` 是固定大小的栈数组 `double match_array[20000] = {0};`，帧号 ≥ 20000 会越界写。KITTI 序列长度远小于此，但换长序列数据要留意。

### 5.2 `candidate_verify`（`:1729`）——估位姿并打分

对每个候选 `BTCMatchList`：

1. 抽样：`skip_len = match_list_.size() / 50 + 1`，最多用 50 个匹配对做 hypothesis。
2. 每个 hypothesis 调 `triangle_solver`（`:1823`）解相对位姿：两帧三角形对应点各减自身 `center_` 得到 `src / ref`，`covariance = src * ref^T`，`JacobiSVD` 得 `V, U`，`rot = V * U^T`；`det(rot) < 0` 时用 `diag(1,1,-1)` 修正；`t = -rot * ref.center_ + src.center_`。
3. 用该位姿对**全部** `match_list_` 投票：三个顶点变换后距离都 `< 3` 记一票（`dis_threshold = 3` 硬编码）。
4. 取票数最高的位姿，`if (max_vote >= 4)` 才继续；否则 `verify_score = -1`。
5. 最终分数：

   ```cpp
   verify_score = plane_geometric_verify(plane_cloud_vec_.back(),                              // 当前帧
                                         plane_cloud_vec_[candidate_matcher.match_id_.second],  // 候选帧
                                         relative_pose);
   ```

   注意 `.back()` 依赖"当前帧已经 push 进 `plane_cloud_vec_`"这个前置条件（见第 3 节顺序表）。

### 5.3 `plane_geometric_verify`（`:1847`）——平面几何内点率

把 source 平面点云按 `(rot, t)` 变换到 target 坐标系，对每个点在 target 平面点云中查 KD-tree 最近邻，满足

```cpp
(normal_inc.norm() < normal_threshold_ || normal_add.norm() < normal_threshold_)   // 法向一致
&& point_to_plane < dis_threshold_                                                 // 点到对方面距离
```

记为内点，返回 `useful_match / source_cloud->size()`，即**平面匹配率 ∈ [0,1]**。

### 5.4 判决

```cpp
// btc.cpp:638
if (best_score > config_setting_.icp_threshold_)   // 室外 0.2
    loop_result = {best_candidate_id, best_score};
else
    loop_result = {-1, 0};                          // 无回环
```

`loop_transform` 与 `loop_std_pair` 返回最优候选的相对位姿与匹配对。

```cpp
    position.x = (int)(single_std.triangle_[0] + 0.5);   // 边长×5 后四舍五入
    position.y = (int)(single_std.triangle_[1] + 0.5);
    position.z = (int)(single_std.triangle_[2] + 0.5);
    data_base_[position].push_back(single_std);
}
```

- `BTC_LOC` 声明了 `x,y,z,a,b,c` 六个成员，但 `operator==` 与 `std::hash` 只使用 **x,y,z**（`a,b,c` 的比较被注释掉）→ 哈希键实质是"三角形三边长（量化后）"。
- 哈希函数：`(((z * 116101) % 1e10 + y) * 116101) % 1e10 + x`（`HASH_P = 116101`，`MAX_N = 1e10`）。
- 数据库：`std::unordered_map<BTC_LOC, std::vector<BTC>> data_base_`，只增不减；时间间隔过滤在检索侧做。

## 8. 中间容器与内存增长

`BtcDescManager` 中四个容器全部**只增不减**，运行时长与内存线性相关：

| 容器 | 追加位置 | 内容 | 内存量级（每帧） |
| --- | --- | --- | --- |
| `std::vector<BTC> btcs_vec`（局部） | 每帧 | 三角形描述子 | 数千~上万 × (3+3+3 个 double + 3 个 50bit 向量 + 头) |
| `history_binary_list_` | `btc.cpp:564` | 每帧全部二值描述子 | 数百 |
| `plane_cloud_vec_` | `btc.cpp:545` | 每帧体素级平面点云 | 与平面数同阶 |
| `key_cloud_vec_` | `place_recognition.cpp:225` | 每帧 0.5 m 降采样世界系云 | 大量点 |
| `data_base_` | `btc.cpp:656` | 全局三角形库 | 累积所有帧 |

大规模序列（数万帧）需要自己加窗口/清理策略，当前代码没有。
