### 2.2 加载方式与键名映射

`load_config_setting`（`src/src/btc.cpp:12`）用 **OpenCV `cv::FileStorage`** 读 YAML，因此配置文件首行必须是 `%YAML:1.0`；打开失败直接 `exit(-1)`（无容错）。

**⚠ 关键：YAML 里的键名与 C++ 成员名有两处不一致**，改配置时容易踩：

| YAML 键 | C++ 成员 | 说明 |
| --- | --- | --- |
| `max_constrait_dis` | `non_max_suppression_radius_` | 拼写是 `constrait`（原文如此） |
| `triangle_resolution` | `std_side_resolution_` | 语义为"三角形边长量化分辨率" |

其余 23 个键与成员同名。完整列表见 `src/src/btc.cpp:22-50`。

> 若 YAML 缺某个键，`cv::FileStorage` 返回空节点 → 赋值为 0（不报错）。这会静默把参数置 0，例如缺 `voxel_size` 会导致体素化退化。改配置时务必对齐键名。

## 3. `Plane`（`src/include/btc.h:90`）

```cpp
class Plane {
 public:
  Eigen::Vector3d p_center_;          // 供 PointXYZINormal 用的中心
  Eigen::Vector3d center_;            // 拟合中心（点均值）
  Eigen::Vector3d normal_;            // 单位法向（最小特征值对应特征向量）
  Eigen::Matrix3d covariance_;        // 3×3 协方差
  float radius_;                      // sqrt(最大特征值)
  float min_eigen_value_;             // 最小特征值（平面度判据）
  float d_;                           // 平面方程常数项 d = -(normal·center)
  int id_;                            // 合并归属标记（0 = 未归属）
  int sub_plane_num_;                 // 合并了多少个子平面
  int points_size_;                   // 点数
  bool is_plane_;                     // 是否被判为平面
};
```

平面方程即 `normal_ · x + d_ = 0`，点到平面有符号距离 `dis = normal_ · p + d_`。

## 4. `BinaryDescriptor`（`src/include/btc.h:73`）

```cpp
class BinaryDescriptor {
 public:
  std::vector<bool> occupy_array_;   // 长度 = (proj_dis_max - proj_dis_min)/high_inc，室外 50
  unsigned char summary_;            // occupy_array_ 中 true 的个数（饱和度）
  Eigen::Vector3d location_;         // 关键点三维坐标（世界系）
};
```

- `summary_` 是 `unsigned char`（上限 255），室外 50 bit 场景安全；但若把 `proj_dis_max_/min_/high_inc_` 调成 >255 个箱，会**溢出**。
- `std::vector<bool>` 是位压缩特化，`binary_similarity` 逐位比较计数。

## 5. `BTC`（`src/include/btc.h:80`）

```cpp
class BTC {
 public:
  Eigen::Vector3d triangle_;         // 三条边长 × (1/std_side_resolution_)，即 ×5
  Eigen::Vector3d angle_;            // ⚠ 未初始化随机值，无人读取
  Eigen::Vector3d center_;           // 三角形三个顶点的质心
  unsigned short frame_number_;      // 帧号（16 位，>65535 会回绕）
  BinaryDescriptor binary_A_;        // 顶点 A（最短边对侧）的二值描述子
  BinaryDescriptor binary_B_;        // 顶点 B
  BinaryDescriptor binary_C_;        // 顶点 C
};
```

- `triangle_` 存储的是**排序后**的边长 `(l1 ≤ l2 ≤ l3) × 5`，故描述子对顶点顺序不敏感。
- 顶点与边的对应关系通过 `generate_btc` 中的位编码 `l1/l2/l3`（`btc.cpp:1508` 附近）反推，保证 `binary_A/B/C` 与排序后顶点一一对应。
- `frame_number_` 是 `unsigned short`，而 `GenerateBtcDescs` 收到的是 `int frame_id`，直接赋值会截断。

## 7. 哈希键

### 7.1 `VOXEL_LOC`（`src/include/btc.h:117`）

```cpp
class VOXEL_LOC {
 public:
  int64_t x, y, z;
  bool operator==(const VOXEL_LOC &other) const;
};
// 哈希：(((z * HASH_P) % MAX_N + y) * HASH_P) % MAX_N + x
#define HASH_P 116101
#define MAX_N 10000000000
```

两个用途：
1. 体素化阶段的空间网格键（坐标 = 点坐标 / 体素边长取整）。
2. `generate_btc` 帧内三角形去重键（坐标 = `a*1000, b*1000, c*1000`）。

### 7.2 `BTC_LOC`（`src/include/btc.h:141`）

```cpp
class BTC_LOC {
 public:
  int x, y, z, a, b, c;   // 名义上 6 维
  bool operator==(const BTC_LOC &other) const;  // 实际只比较 x, y, z
};
```

`a, b, c` 的比较在实现里被注释掉，所以**哈希键只有三维**——这正是"用三边长当键"的设计，`data_base_` 的键 = 三角形三边长的整数量化值。

**重要事实**：`grep` 全文件，`leaves_` 与 `octo_state_` 没有任何读写点，`init_octo_tree()`（`src/src/btc.cpp:128`）的完整实现是

```cpp
void OctoTree::init_octo_tree() {
  if (voxel_points_.size() > config_setting_.voxel_init_num_) {
    init_plane();
  }
```

即**没有八叉树细分**。`OctoTree` 实质是"一个体素的点集 + 一次 PCA 平面拟合"，名字是历史遗留。想改造成真正的多尺度结构，需要自己实现递归。

## 12. 线程与并发要点

| 位置 | 机制 | 备注 |
| --- | --- | --- |
| `init_voxel_map` 平面检测（`btc.cpp:792`） | `std::execution::par_unseq` | 各体素独立，无写冲突 |
| `candidate_selector` 检索（`btc.cpp:1570` 内） | `par_unseq` + `std::mutex` 保护 `match_array` | 读 `data_base_` 属并发只读，安全 |
| `candidate_verify` 投票 | `par_unseq` + mutex 写 `vote_list` | 同上 |

因为依赖 `par_unseq`，CMake 中必须链接 TBB，否则 `std::execution` 策略会退化为串行（GCC 实现需要 libtbb）。
